# Архитектура

Этот документ описывает, каким будет Espresso: назначение, решения,
устройство программы, этапы работ и открытые вопросы. Он живой: каждое
изменение устройства, интерфейсов, решений или планов отражается здесь в
той же работе, а в конце документа ведётся журнал изменений.


## 1. Назначение

Espresso — самостоятельный терминал с языком Форт на плате LilyGO TTGO
VGA32 v1.4. К плате подключаются монитор VGA, клавиатура и мышь PS/2,
SD-карта и динамик; компьютер не нужен. Оболочка терминала — движок
Форта ff: пользователь набирает команды в редакторе строки, ff их
выполняет. Определения слов правятся в полноэкранном редакторе, который
запускает слово Форта. Тот же терминал доступен с ПК через
последовательный порт USB.


## 2. Оборудование

| Узел | Подключение |
|---|---|
| Процессор | ESP32-PICO-D4: два ядра Xtensa LX6 по 240 МГц, 520 КБ ОЗУ без PSRAM, 4 МБ флеш-памяти в корпусе |
| VGA | по 2 разряда на канал (первым указан старший), 64 цвета: красный — GPIO22 и GPIO21, зелёный — GPIO19 и GPIO18, синий — GPIO5 и GPIO4; строчный синхроимпульс — GPIO23, кадровый — GPIO15 |
| Клавиатура PS/2 | порт 0: CLK — GPIO33, DATA — GPIO32; оба порта обслуживает сопроцессор ULP |
| Мышь PS/2 | порт 1: CLK — GPIO26, DATA — GPIO27 |
| Звук | встроенный ЦАП, GPIO25 |
| SD-карта | шина SPI (выводы — в `esp::sd_card`), файловая система FAT в каталоге `/sdcard` |
| Кнопки | K1 — GPIO36 (только вход, внешняя подтяжка); K2 — сброс |
| USB | преобразователь USB — UART0, 115200 бод: прошивка, журнал ESP-IDF, терминал |


## 3. Главные решения

Решения приняты 2026-11-24 и 2026-11-26 по ответам на вопросы.

| Вопрос | Решение |
|---|---|
| Оболочка | движок ff (github.com/stoneagesoft/ff) — подмодуль git в `src/3rdparty/ff`; это сторонний код, его стиль не меняется |
| Ячейки ff | 32-разрядные (`FF_32BIT`), вещественные числа одинарной точности: блок плавающей точки ESP32 работает только с ними |
| Экран при запуске | 640 × 480, 4 цвета, шрифт Terminus 10 × 18: 64 × 26 знакомест, буфер кадра 75 КБ; режим меняется словом Форта |
| Язык | пока английский; ввод только латиницы. Русский ввод и русские сообщения ff — позже; кириллица в шрифте уже есть |
| Управление экраном | подмножество VT220 и альтернативный экран xterm в потоке вывода (6.2, 6.6) |
| Устройство терминала | пространство имён `esp::vt`: разборщик VT220 по автомату Пола Уильямса, модель экрана, разбор ввода и редактор строки (раздел 6) |
| Выделение | работает и в 2-цветных режимах: инверсией, подчёркиванием, жирным шрифтом; цвет его только дополняет |
| Последовательный порт | зеркало всего вывода и ввод с терминала ПК |
| Клавиши | байты последовательностей VT220, как от настоящего терминала: клавиатура PS/2 переводится в них; Форт получает байты словом `key`, а разобранные клавиши — словами `ekey` стандарта Forth 2012 (6.3, 7.5) |
| Редактор строки | история (хранится на SD-карте), дополнение слов по Tab в стиле bash, многострочные определения, клавиши в стиле Emacs |
| Полноэкранный редактор | текст определения даёт `see`; комментарии будут храниться вместе со словами (доработка ff); редактор работает на альтернативном экране (6.6) |
| После правки слова | слова, определённые после него, пересобираются, так что вызывающие слова получают новую версию |
| Переменные и массивы | значения сохраняются при пересборке и записываются словом `save` |
| Сохранение словаря | слово `save` пишет словарь на SD-карту; при запуске он загружается |
| Кнопка K1 | короткое нажатие прерывает выполнение, долгое заново ищет клавиатуру и мышь |
| Проверка платы | остаётся словом Форта `board-test` |

## 5. Устройство программы

### 5.1. Слои

```
┌──────────────────────────────────────────────────────┐
│ Приложение esp::app: запуск, кнопка K1               │
├────────────────────────┬─────────────────────────────┤
│ Полноэкранный          │ Оболочка esp::shell: ff,    │
│ редактор esp::editor   │ слова, история, дополнение  │
├────────────────────────┴─────────────────────────────┤
│ Терминал esp::vt: экран знакомест, поток вывода,     │
```

ANSI в потоке вывода, а не прямо на холсте. Поэтому всё, что видно на
мониторе, так же выглядит и в терминале ПК.

### 5.3. Задачи и ядра

| Задача | Ядро | Что делает |
|---|---|---|
| Оболочка (новая) | 0 | цикл оболочки, выполнение Форта, полноэкранный редактор; стек с запасом (предварительно 16 КБ, уточнить замером): у главной задачи ESP-IDF всего 3,5 КБ |
| Ввод (новая) | 0 | переводит нажатия клавиш PS/2 в последовательности VT220 (6.3) и вместе с байтами последовательного порта кладёт в очередь ввода; обрабатывает Ctrl+C (7.6) |
| Главная (`app_main`) | 0 | запуск, затем, как сейчас, опрос кнопки K1 каждые 10 мс |
| Мигание курсора | 0 | таймер `esp_timer`; его обратные вызовы выполняет задача `esp_timer` на ядре 0 |
| Обработчик прерывания VGA | 1 (`esp::VIDEO_TASKS_CORE`) | готовит строки развёртки; задача, которая выполняет команды рисования драйверов с палитрой, работает на ядре 0 (`esp::core_usage::quiet_core()`) |
| Клавиатура и мышь PS/2 | любое | задачи драйверов, как сейчас, без привязки к ядру |
| Обработчик прерывания звука | 0 (`esp::core_usage::quiet_core()`) | как сейчас |

Экран терминала меняют задача оболочки и таймер курсора, поэтому
изменения экрана идут под мьютексом терминала.

Сторожевой таймер задач ESP-IDF следит за задачами простоя обоих ядер и
срабатывает, если задача простоя 5 с не получала процессор. Долгий цикл
Форта в задаче оболочки отнимал бы ядро 0 у его задачи простоя. Поэтому
обратный вызов `watchdog` движка ff (ff вызывает его через каждые 65 536
команд) смотрит на часы и раз в 100 мс (предварительно) отдаёт процессор
на один такт планировщика: `vTaskDelay(1)` — 1 мс при частоте
планировщика 1000 Гц, около 1 % скорости.


## 6. Терминал `esp::vt`

Терминал состоит из четырёх частей; оболочка и полноэкранный редактор
пользуются им через поток байтов.

| Часть | Что делает |
|---|---|
| `esp::vt::parser` | разбирает поток вывода (6.2) по автомату Пола Уильямса для VT220 и xterm (vt100.net) и собирает знаки из UTF-8; последовательности OSC, DCS и APC разбирает и пропускает, не накапливая |
| `esp::vt::screen` | выполняет разобранные последовательности над сеткой знакомест (6.1): курсор, вид текста, область прокрутки, альтернативный экран (6.6); истории экрана нет |
| `esp::vt::input_parser` | разбирает последовательности клавиш в потоке ввода (6.3) |
| `esp::vt::line_edit` | редактор строки в духе readline (7.4) |

Путь данных: ввод → редактор строки → поток вывода → разборщик → экран.

Разборщик, модель экрана, разбор ввода и редактор строки не зависят от
ESP-IDF и проверяются на ПК: проверки лежат в каталоге `test` и
собираются обычным компилятором, без платы, с санитайзерами адресов и
неопределённого поведения; запуск — `test/run.sh`. Проверки пишут ESC как
`^[`.

### 6.1. Экран

Экран — сетка знакомест; её размер следует из видеорежима и шрифта
10 × 18: 64 × 26 при 640 × 480, 80 × 33 при 800 × 600, 102 × 42 при
1024 × 768. Знакоместо занимает 4 байта:

| Разряды | Что хранится |
|---|---|
| 0–15 | код знака Unicode |
| 16–19 | цвет текста — номер цвета ANSI, 0–15 |
| 20–23 | цвет фона — номер цвета ANSI, 0–15 |
| 24–31 | признаки: жирный, тусклый, курсив, подчёркнутый, инверсия, скрытый; два разряда в запасе |

UTF-8 в знакоместах не хранится: разборщик собирает из байтов UTF-8 код
знака, и знакоместо получает уже код. 16 разрядов хватает, потому что все
знаки шрифта — в основной плоскости Unicode (таблица `CODEPOINTS` шрифта —
из `std::uint16_t`, последний знак — U+FFFD); знак за её пределами шрифт
всё равно не нарисует, и он хранится как U+FFFD. Знаков двойной ширины и
комбинируемых знаков в шрифте нет: один знак — одно знакоместо.

Цвет хранится номером ANSI, а не цветом палитры, и сопоставляется с
палитрой видеорежима при рисовании: смена палитры или режима
перекрашивает экран. Признаки рисует сам вывод знаков: у
`esp::gfx::glyph_options` есть жирный, пониженная яркость, курсив,
подчёркивание, инверсия и пропуск знака.

Сеток две — основная и альтернативная (6.6), каждая около 6,5 КБ при
64 × 26. Основная сетка — главная копия экрана: по ней экран
перерисовывается после смены видеорежима, возврата с альтернативного
экрана или из проверки платы.

- Знакоместо рисуется знаком `esp::gfx::font` с заливкой фона; заново
  рисуются только изменившиеся знакоместа.
- Прокрутка на строку вверх — командой прокрутки холста (драйверы с
  палитрой меняют местами указатели строк, это быстро) и очисткой нижней
  строки.
- Курсор — инвертированное знакоместо; мигает по таймеру (примерно 2 раза
  в секунду) и скрывается, пока экран меняется.
- При 640 × 480 под 26 строками остаются 12 точек; они не используются.

### 6.2. Поток вывода

Всё, что выводит Форт, оболочка и редакторы, — поток байтов UTF-8.
Терминал разбирает его так:

| Байты | Действие |
|---|---|
| печатные знаки | знак в позиции курсора; в конце строки — перенос, внизу экрана — прокрутка |
| `0x07` (BEL) | короткий звук |
| `0x08` (BS) | курсор на знак влево |
| `0x09` (HT) | курсор к следующему столбцу, кратному 8 |
| `0x0A`–`0x0C` (LF, VT, FF) | курсор на строку вниз, у нижнего края области прокрутки — прокрутка; в начало строки курсор не возвращается, как в VT220 (одиночный LF терминал заранее заменяет на CR LF, 6.4) |
| `0x0D` (CR) | начало строки |
| `ESC 7` / `ESC 8` (DECSC / DECRC) | запомнить / вернуть положение курсора и вид текста |
| `ESC D` / `ESC M` (IND / RI) | курсор на строку вниз / вверх, у края области — прокрутка |
| `ESC E` (NEL) | начало следующей строки, у края области — прокрутка |
| `ESC c` (RIS) | полный сброс |
| `ESC [ n A` / `B` / `C` / `D` | курсор вверх / вниз / вправо / влево на n |
| `ESC [ n E` / `F` | курсор в начало n-й строки ниже / выше |
| `ESC [ n G` / `ESC [ n d` | курсор в столбец / строку n |
| `ESC [ r ; c H` или `f` | курсор в строку r, столбец c (с 1) |
| `ESC [ n J` | очистить экран: 0 — от курсора до конца, 1 — от начала до курсора, 2 — весь |
| `ESC [ n K` | очистить строку: 0, 1 и 2 — так же |
| `ESC [ n L` / `M` | вставить / удалить n строк |
| `ESC [ n @` / `P` / `X` | вставить / удалить / стереть n знаков |
| `ESC [ n S` / `T` | прокрутить область вверх / вниз на n строк |
| `ESC [ t ; b r` (DECSTBM) | область прокрутки — строки с t по b |
| `ESC [ s` / `u` | запомнить / вернуть положение курсора |
| `ESC [ … m` | вид текста: 0 — сброс; 1, 2, 3, 4, 7, 8 — жирный, тусклый, курсив, подчёркнутый, инверсия, скрытый; 22–28 — их отмена; 30–37, 90–97, `38;5;n`, `38;2;r;g;b` — цвет текста, 39 — по умолчанию; 40–47, 100–107, `48;5;n`, `48;2;r;g;b` — цвет фона, 49 — по умолчанию; цвета заменяются ближайшими из 16 цветов ANSI |
| `ESC [ ? 7 h` / `l` | перенос в конце строки включить / выключить |
| `ESC [ ? 25 h` / `l` | показать / скрыть курсор |
| `ESC [ ? 1049 h` / `l` | перейти на альтернативный экран / вернуться (6.6) |

Остальные последовательности — OSC, DCS, APC, выбор наборов знаков
VT220 — разбираются и пропускаются. Набор расширяется по мере
надобности; каждое расширение отражается в этой таблице.

### 6.3. Ввод

Ввод — один поток байтов в том виде, в каком его шлёт терминал VT220 или
xterm. С последовательного порта байты приходят уже в таком виде; нажатия
клавиш PS/2 (раскладка US, как сейчас) задача ввода переводит в те же
байты и кладёт в ту же очередь:

| Клавиша | Байты |
|---|---|
| знак | его байты UTF-8 (пока только латиница) |
| Ctrl+буква | управляющий знак 1–26 |
| Enter, Tab, Backspace, Esc | 13 (CR), 9 (HT), 127 (DEL), 27 (ESC) |
| Alt+клавиша | ESC, затем байты клавиши |
| ↑, ↓, →, ← | `ESC [ A`, `ESC [ B`, `ESC [ C`, `ESC [ D` |
| Home, End | `ESC [ H`, `ESC [ F` |
| Insert, Delete, PgUp, PgDn | `ESC [ 2 ~`, `ESC [ 3 ~`, `ESC [ 5 ~`, `ESC [ 6 ~` |
| F1–F4 | `ESC O P`, `ESC O Q`, `ESC O R`, `ESC O S` |
| F5–F12 | `ESC [ 15 ~`, `ESC [ 17 ~`, `ESC [ 18 ~`, `ESC [ 19 ~`, `ESC [ 20 ~`, `ESC [ 21 ~`, `ESC [ 23 ~`, `ESC [ 24 ~` |
| особая клавиша с Shift, Alt, Ctrl | второй параметр — 1 плюс признаки (Shift — 1, Alt — 2, Ctrl — 4): Ctrl+← — `ESC [ 1 ; 5 D`, Shift+F5 — `ESC [ 15 ; 2 ~`, Shift+F1 — `ESC [ 1 ; 2 P` |

Последовательности в потоке ввода разбирает `esp::vt::input_parser`
(раздел 6) — для редактора строки, полноэкранного редактора и слова
`ekey` (7.5). Он понимает и варианты, которые шлют другие терминалы ПК:
Home и End как `ESC [ 1 ~` и `ESC [ 4 ~` или как `ESC O H` и `ESC O F`.
ESC, за которым 50 мс (предварительно) ничего не пришло, — клавиша Esc;
Backspace — и 127, и 8 (Ctrl+H).

Ctrl+C задача ввода обрабатывает особо (7.6).

### 6.4. Последовательный порт

Одиночный LF в потоке вывода терминал заменяет на CR LF, как терминал
Unix, — до разборщика и до UART0, поэтому монитор и терминал ПК получают
одно и то же. Весь поток вывода идёт ещё и в UART0, а байты, принятые с
UART0, поступают во ввод. Окно терминала ПК должно
быть не меньше экрана (64 × 26 при запуске), иначе полноэкранный
редактор в нём выглядит неправильно.

В UART0 пишет и журнал ESP-IDF. Строки, записанные мимо терминала, сбили
бы экран терминала ПК (положение курсора, альтернативный экран), поэтому
после запуска терминала журнал идёт через него (`esp_log_set_vprintf()`)
и попадает и на монитор, и в терминал ПК; уровень журнала тогда —
предупреждения. Сообщения ранней загрузки, до запуска терминала, идут в
UART0 как есть.

Альтернативный экран (6.6) — расширение xterm, а не VT220: его понимают
xterm-совместимые терминалы ПК, в окне которых работают picocom, tio или
`idf.py monitor`.

### 6.5. Видеорежимы и палитра

При запуске — 640 × 480, 4 цвета (`esp::vga::vga4_controller`). Слово
Форта переключает видеорежим на один из проверенных на плате: 640 × 480
с 16, 8, 4 и 2 цветами, 800 × 600 с 4 и 2 цветами, 1024 × 768 с 2
цветами в двух развёртках. Видеоконтроллер прежнего режима
останавливается (`end()`) и уничтожается, как в проверке платы; размер
сетки меняется, экран очищается.

Палитра терминала из 4 цветов задаётся словом; предлагается чёрный фон,
светло-серый текст, жёлтый для приглашения и выделения, красный для
ошибок. Цвета из последовательностей ANSI заменяются ближайшими цветами
палитры.

В 2-цветных режимах (640 × 480, 800 × 600 и 1024 × 768) цвет ничего не
различает, поэтому выделение в оболочке и редакторах делается признаками
— инверсией, подчёркиванием, жирным шрифтом, — а цвет его только
дополняет.

### 6.6. Альтернативный экран

`ESC [ ? 1049 h` запоминает курсор и вид текста (как `ESC 7`),
переключает вывод на альтернативную сетку и очищает её. `ESC [ ? 1049 l`
возвращает основную сетку, курсор и вид текста и перерисовывает экран по
основной сетке: буфер кадра у VGA один, а перерисовка 64 × 26 знакомест
займёт, по оценке, десятки миллисекунд. У каждой сетки — свои курсор, вид
текста и область прокрутки. Обе сетки выделяются при включении
видеорежима, чтобы переход на альтернативный экран не срывался из-за
нехватки памяти.

Полноэкранный редактор работает на альтернативном экране: после выхода
из него экран оболочки возвращается таким, каким был, — и на мониторе, и
в терминале ПК.


## 7. Оболочка `esp::shell`

### 7.1. Движок ff

ff — библиотека на C17. Всё состояние Форта хранится в экземпляре
`ff_t`; общая для всех экземпляров только таблица встроенных слов,
которую ff строит при первом `ff_new()`. Сама ff ничего не печатает и
не читает: вывод, диагностика, файлы и пределы — это обратные вызовы и
поля `ff_platform_t`, которые даёт хост (7.2). Текст выполняется
функцией `ff_eval()`; начатое в одном вызове (определение, комментарий)
продолжается в следующем.

- Исходники — подмодуль git `src/3rdparty/ff`. Автоматический сбор
  каталогов компонента `src` (`cmake/tools.cmake`) этот каталог
  пропускает: иначе в сборку попали бы тесты, примеры и фаззер ff, а в
  пути заголовков — его сторонние библиотеки. В документацию Doxygen ff
  тоже не входит: `doc/Doxyfile` исключает весь `src/3rdparty`.
- ff собирается отдельной статической библиотекой CMake внутри
  компонента `src` из тех же исходников, что собирает его собственный
  `CMakeLists.txt`, со своими путями заголовков и определениями `FF_*`;
  `ff_version.h` получается из `ff_version.h.in`. Собственный
  `CMakeLists.txt` ff для этого не годится: он рассчитан на
  самостоятельную сборку (пути от `CMAKE_SOURCE_DIR`, установка,
  pkg-config).
- Пути заголовков ff и Espresso не смешиваются: у обоих своя `utf8.h`,
  и копии различаются.
- Параметры сборки (предложение):

| Параметр | Значение | Почему |
|---|---|---|
| `FF_32BIT` | определён | 32-разрядные ячейки и вещественные числа одинарной точности (раздел 3) |
| `FF_SAFE_MEM` | включён | неверный адрес в набранном коде даёт ошибку Форта, а не перезагрузку платы с потерей несохранённой работы; цена, по README ff, — около 10–20 % скорости |
| `FF_WITH_SYSTEM` | выключен | слову `system` на плате нечего запускать |
| `FF_WITH_FILES` | включён | файловые слова и `load` — для файлов на SD-карте через стандартную библиотеку C и VFS ESP-IDF |
| `FF_WITH_TR` | выключен | интерфейс пока английский, а без переводов меньше флеш-памяти; переводы включатся вместе с русским вводом |

### 7.2. Обратные вызовы ff

| Поле `ff_platform_t` | Что делает в Espresso |
|---|---|
| `vprintf` | форматирует текст и отдаёт его в поток вывода терминала |
| `vtracef` | трассировку, предупреждения и сообщения ff — в поток вывода выделенным цветом; ошибки ff сюда не передаёт, их даёт `ff_strerror()` |
| `watchdog` | отдаёт процессор задачам простоя (5.3); `watchdog_interval` — по умолчанию, 65 536 команд |
| `deny` | ничего не запрещает |
| `open_file` | относительные пути отсчитываются от `/sdcard`; без SD-карты — ошибка |
| `run_command` | не нужен: слова `system` нет |
| `mem_limit` | предел памяти слов и строк Форта (сверх него — ошибка −8), чтобы её хватило экрану; предварительно 64 КБ, уточнить замером |
| `lang` | не задан — английский |

### 7.3. Цикл оболочки

1. Создать ff (`ff_new()`) и зарегистрировать слова терминала (7.5).
2. Вывести заставку: версию Espresso и `ff_banner()`.
3. Загрузить словарь с SD-карты (7.7).
4. Повторять: показать приглашение `ff_prompt()`, прочитать строку
   редактором строки, выполнить её `ff_eval()`, добавить в историю. При
   ошибке вывести `ff_strerror()` и отметить место ошибки в строке
   (`ff_err_pos()`).

Приглашение ff показывает, что определение ещё не закрыто: `▶` — обычное,
`:▶` — внутри определения, `(▶` — внутри комментария. Так работают
многострочные определения: каждая строка выполняется сразу, а ff
продолжает открытое определение со следующей строки. Если в строке
посреди определения ошибка, ff сам убирает недописанное определение.

Строки, набранные вне определений, и строки, которые кладут на стек
`accept` и `parse`, ff держит во временной области. Она растёт до
предела памяти, пока хост не освободит её (`ff_release_strings()`);
после этого строка, адрес которой лежит в переменной, становится
недействительной (сборка с `FF_SAFE_MEM` даёт тогда ошибку, а не сбой).
Когда оболочке освобождать эту область — открытый вопрос (раздел 14).

### 7.4. Редактор строки

Редактор строки — `esp::vt::line_edit` (раздел 6). Эхо, перерисовку и
движение курсора он выводит только байтами в поток терминала, поэтому
одинаково работает на мониторе и в терминале ПК. Клавиши:

| Действие | Клавиши |
|---|---|
| на знак влево / вправо | ← / →, Ctrl+B / Ctrl+F |
| на слово влево / вправо | Ctrl+← / Ctrl+→, Alt+B / Alt+F |
| в начало / конец строки | Home / End, Ctrl+A / Ctrl+E |
| удалить знак слева / под курсором | Backspace, Ctrl+H / Delete, Ctrl+D |
| удалить слово слева / справа | Ctrl+W, Alt+Backspace / Alt+D |
| удалить до конца / от начала строки | Ctrl+K / Ctrl+U |
| вставить последнее удалённое | Ctrl+Y |
| предыдущая / следующая строка истории | ↑ / ↓, Ctrl+P / Ctrl+N |
| поиск по истории назад | Ctrl+R |
| дополнить слово | Tab |
| выполнить строку | Enter |
| очистить строку | Ctrl+C |
| очистить экран и вывести строку заново | Ctrl+L |

- Tab при одном варианте дополняет слово целиком, при нескольких — до
  общего начала; второй Tab подряд выводит список вариантов. Варианты —
  имена слов словаря без учёта регистра латиницы, как их ищет
  `ff_find()`; перебирать слова из C ff пока не умеет (раздел 9).
  Подсказка серым после курсора не подходит: в 2-цветных режимах её не
  отличить от набранного текста.
- Курсор, удаление и движение по словам идут по целым знакам UTF-8, а не
  по байтам: иначе двухбайтовый знак кириллицы разрезался бы.
- Длинная строка переносится на следующие строки экрана; наибольшая
  длина строки — 256 байт (предварительно).
- История — последние строки в кольцевом буфере на 8 КБ, около 100
  строк обычной длины; пустые строки и повторы предыдущей в неё не
  попадают. Каждая новая строка
  дописывается в файл на SD-карте (раздел 11), при запуске история
  читается из него.

### 7.5. Слова терминала

Хост добавляет в ff свои слова (`ff_register()`); у каждого — справка
для `man` (пока на английском). Имена — предложение:

| Слово | Стек | Что делает |
|---|---|---|
| `key` | ( -- c ) | ждёт байт ввода и кладёт его (6.3): у знака кириллицы таких байтов два, у особой клавиши — целая последовательность |
| `key?` | ( -- f ) | есть ли байт в очереди ввода |
| `ekey` | ( -- x ) | ждёт событие клавиатуры: собирает знак UTF-8 или последовательность особой клавиши в одно значение — код знака или номер особой клавиши от `0x110000` с признаками Shift, Alt и Ctrl в старших разрядах |
| `ekey?` | ( -- f ) | есть ли событие клавиатуры |
| `ekey>char` | ( x -- c f ) | f — истина, если x — знак, и тогда c — его код; иначе c — это x |
| `ekey>fkey` | ( x -- u f ) | f — истина, если x — особая клавиша, и тогда u — её номер с признаками; иначе u — это x |
| `k-left` … `k-f12`, `k-shift-mask`, `k-ctrl-mask`, `k-alt-mask` | ( -- u ) | номера особых клавиш и признаки — для сравнения с результатом `ekey>fkey` |
| `accept` | ( -- s ) | читает строку через редактор строки и кладёт её адрес (строка — во временной области ff, 7.3) |
| `page` | ( -- ) | очищает экран |
| `at-xy` | ( x y -- ) | ставит курсор в столбец x, строку y |
| `fg`, `bg` | ( n -- ) | цвет текста / фона — номер цвета ANSI, 0–15 (6.1) |
| `ms` | ( n -- ) | пауза на n мс |
| `beep` | ( -- ) | короткий звук |
| `tone` | ( частота мс -- ) | звук заданной частоты |
| `video-mode` | ( n -- ) | переключает видеорежим (6.5) |
| `palette!` | ( r g b n -- ) | задаёт цвет палитры |
| `edit` | ( "имя" -- ) | открывает определение в полноэкранном редакторе |
| `save` | ( -- ) | записывает словарь на SD-карту |
| `board-test` | ( -- ) | запускает проверку платы |

`page`, `at-xy`, `fg` и `bg` выводят последовательности ANSI, поэтому
действуют и на экране, и в терминале ПК.

`ekey`, `ekey?`, `ekey>char`, `ekey>fkey` и константы клавиш — слова
стандарта Forth 2012 (расширение Facility): `k-left`, `k-right`, `k-up`,
`k-down`, `k-home`, `k-end`, `k-prior`, `k-next`, `k-insert`,
`k-delete`, `k-f1` … `k-f12`.

### 7.6. Прерывание

Ctrl+C (с клавиатуры или из терминала ПК) и короткое нажатие K1
прерывают выполняющийся код Форта: задача ввода (для K1 — главная
задача) вызывает `ff_request_abort()`. ff останавливается на ближайшем
переходе или вызове слова, и `ff_eval()` возвращает ошибку
`FF_ERR_ABORTED`, которую не перехватывает никакой `catch`; оболочка
сообщает о прерывании и выводит приглашение.

- Слова терминала, которые ждут (`key`, `ekey`, `accept`, `ms`), ждут
  не только своего события, но и просьбы о прерывании; получив её, они
  сразу возвращаются, и ff прерывается на следующем же слове.
- Просьбу, пришедшую между вызовами, ff сбрасывает в начале следующего
  вызова. Поэтому оболочка отмечает, когда выполняется код Форта, и
  Ctrl+C и K1 прерывают только тогда; в остальное время Ctrl+C —
  обычная клавиша: в редакторе строки она стирает набранное.
- Полноэкранный редактор, хотя его и запускает слово `edit`, на время
  своей работы снимает эту отметку: в нём Ctrl+C — обычная клавиша, а K1
  не прерывает. Пересборку (8.3) прервать можно.

### 7.7. Сохранение и загрузка словаря

- `save` записывает в `/sdcard/espresso.ff` все слова, созданные кодом
  Форта (встроенные слова ff и слова терминала в файл не попадают), по
  порядку определения: текст каждого даёт `see` вместе с комментариями.
  После определений идёт код, который восстанавливает значения
  переменных и массивов. Прежний файл переименовывается в
  `espresso.bak`.
- При запуске оболочка загружает `/sdcard/espresso.ff` (`ff_load()`),
  если он есть; ошибки выводятся, но оболочка запускается в любом случае.
- Без SD-карты `save` сообщает об ошибке, словарь не загружается, история
  живёт только в памяти.


## 8. Полноэкранный редактор `esp::editor`

### 8.1. Вызов и экран

`edit имя` открывает текст определения, который даёт `see` вместе с
хранимыми комментариями. Для нового имени открывается заготовка
`: имя ;`. Экран редактора при 64 × 26:

- строка 1 — заголовок в инверсии: имя слова, признак изменений;
- строки 2–25 — текст;
- строка 26 — в инверсии: подсказка по клавишам, сообщения и ошибки.

Редактор работает на альтернативном экране (6.6) и рисует через поток
вывода терминала, поэтому работает и в терминале ПК. Текст он
прокручивает областью прокрутки и вставкой и удалением строк (6.2) — это
дёшево и на последовательной линии; клавиши разбирает
`esp::vt::input_parser`.

### 8.2. Клавиши

Движение по строке и удаление — как в редакторе строки (7.4); кроме
того:

| Действие | Клавиши |
|---|---|
| на строку вверх / вниз | ↑ / ↓, Ctrl+P / Ctrl+N |
| на экран вверх / вниз | PgUp / PgDn |
| в начало / конец текста | Ctrl+Home / Ctrl+End |
| новая строка с отступом предыдущей | Enter |
| отступ на 4 пробела | Tab |
| проверить, сохранить и пересобрать (8.3) | Ctrl+S или F2 (для терминалов ПК, которые оставляют Ctrl+S себе) |
| выйти; если текст изменён и не сохранён — спросить | Esc |

### 8.3. Сохранение и пересборка

ff, как классический Форт, при новом определении того же имени оставляет
слова, скомпилированные раньше, со старой версией. Чтобы они получили
новую, редактор пересобирает всё, что определено после правленого слова;
`forget` в ff как раз убирает слово вместе со всеми словами после него.

1. Запоминает текст (по `see`, с комментариями) всех слов, определённых
   после старой версии, по порядку, и значения переменных и массивов —
   этих слов и самого правленого, если оно переменная или массив.
2. Компилирует новый текст как новое определение. При ошибке ff сам
   убирает недописанное определение, словарь остаётся прежним, курсор
   встаёт на место ошибки (`ff_err_line()`, `ff_err_pos()`), сообщение —
   в нижней строке.
3. Забывает старую версию (`forget`); с ней уходят все слова после неё,
   в том числе пробное определение из шага 2.
4. Выполняет новый текст, затем запомненные тексты по порядку и
   восстанавливает значения (массива — если его размер не изменился).
5. Если какое-то слово не компилируется, пересборка останавливается, а
   это слово открывается в редакторе; слова до него уже пересобраны.

Ограничения:

- ff не забывает слово, пока выполняется оно или любое слово после него.
  Если `edit` вызван не из командной строки, а из такого слова,
  пересборка невозможна, и редактор сообщает об этом.
- Новый текст выполняется дважды (шаги 2 и 4), поэтому в нём должно
  быть только определение: код вне определения выполнился бы два раза.
- Пересборка верна, только если текст `see` компилируется обратно в то
  же самое слово для всех видов слов (раздел 9).


## 9. Доработки ff

Делаются в репозитории ff и попадают в Espresso обновлением подмодуля.

1. Комментарии хранятся вместе со словом, и `see` выводит их на своих
   местах.
2. Текст `see` компилируется обратно в то же слово для всех видов слов,
   и это проверяют тесты ff. Сейчас это не так для переменных: `see`
   выводит `create x ( 1 cell reserved )`, а такой текст создаёт слово
   без памяти. Не так и для `defer` (назначение `' y is x` стоит в
   комментарии) и для слов, созданных через `does>`: они выводятся
   описанием, а не кодом.
3. Интерфейс C для словаря: перебор слов по порядку определения (для
   дополнения, `save` и пересборки), вид слова, адрес и размер данных
   переменных и массивов (для их значений).
4. 32-разрядная сборка: компилятор Xtensa из ESP-IDF с `FF_32BIT` без
   предупреждений и тесты ff в 32-разрядной сборке на ПК (`-m32`).
5. По желанию: `CMakeLists.txt` ff, который можно подключить через
   `add_subdirectory()` (пути от `CMAKE_CURRENT_SOURCE_DIR`, без
   установки и pkg-config); тогда Espresso не ведёт свой список файлов ff
   (7.1).


## 10. Память

ОЗУ без PSRAM — около 520 КБ, из них свободной кучи после запуска ESP-IDF
заметно меньше; точные цифры — замером на первом этапе.

| Что | Объём |
|---|---|
| буфер кадра 640 × 480, 4 цвета | 75 КБ |
| очередь команд рисования VGA (1024 команды) | ≈ 16 КБ |
| дескрипторы DMA и строки развёртки | ≈ 15 КБ |
| две сетки знакомест 64 × 26: основная и альтернативная (6.6) | 13 КБ |
| стек задачи оболочки | 16 КБ (предварительно) |
| слова и строки Форта (`mem_limit`) | 64 КБ (предварительно) |
| история строк: кольцевой буфер (7.4) | 8 КБ |
| строки редактора строки: набираемая, сохранённая, поиск | ≈ 1 КБ |
| текст в полноэкранном редакторе и при пересборке | до ≈ 8 КБ |
| звук, PS/2, SD-карта | несколько КБ |

Видеорежим с большим буфером кадра (640 × 480 при 16 цветах — 150 КБ)
оставляет Форту меньше памяти.

## 12. Кнопка K1 и проверка платы

- Короткое нажатие K1 прерывает выполнение Форта, как Ctrl+C (7.6).
- Долгое нажатие (предварительно от 1 с) заново ищет клавиатуру и мышь,
  подключённые после запуска.
- `board-test` останавливает и освобождает видеоконтроллер терминала
  (двум буферам кадра памяти не хватит) и запускает нынешнюю проверку
  платы со всеми её клавишами (F1–F10, F12) и мышью; задача ввода на это
  время отдаёт ей клавиатуру. Выход — в оболочку: терминал включает свой
  видеорежим и перерисовывает экран по сетке знакомест. Клавиша выхода —
  открытый вопрос (раздел 14).


## 13. Этапы работ

Терминал делается раньше Форта: он от Форта не зависит, а до ff его
ведёт временная тестовая оболочка.

1. Терминал `esp::vt`: разборщик, экран с альтернативным экраном,
   рисование через `esp::gfx`, курсор, ввод (клавиатура PS/2 →
   последовательности VT220, последовательный порт), зеркало вывода,
   журнал ESP-IDF через терминал (6.4). Временная тестовая оболочка: эхо
   и несколько команд — очистка экрана, проверка признаков и цветов,
   смена видеорежима, текст проверки VT, `board-test`; потом ff заменяет
   её команды. Проверки разборщика и экрана на ПК (раздел 6).
2. Редактор строки `esp::vt::line_edit`: клавиши, курсор по знакам UTF-8,
   дополнение в стиле bash по постоянному списку слов, история на
   SD-карте.
3. ff на ESP32: подмодуль, сборка (7.1), оболочка на терминале — задача
   оболочки, цикл, многострочные определения, слова терминала,
   прерывание (Ctrl+C, K1); замеры памяти и скорости.
4. Доработки ff (раздел 9), первой — интерфейс C для словаря: к нему
   подключается дополнение.
5. `save` и загрузка словаря при запуске, со значениями переменных.
6. Полноэкранный редактор и пересборка.
7. Слова `video-mode`, `palette!` и `board-test`.

Позже: русский ввод (раскладка ЙЦУКЕН, переключение раскладки, коды
Unicode в событиях клавиатуры) и русские сообщения ff; мышь в редакторе;
другие слова для звука.


## 14. Открытые вопросы

- Имена слов терминала, не входящих в стандарт Forth 2012 (7.5).
- Палитра из 4 цветов (6.5).
- Параметры сборки ff (7.1): `FF_SAFE_MEM` и `FF_WITH_TR` — предложение,
  его нужно подтвердить.
- Сборка ff: свой список файлов в Espresso (7.1) или встраиваемый
  `CMakeLists.txt` в ff (доработка 5 из раздела 9).
- Когда оболочке освобождать временные строки ff (7.3): например, после
  каждой строки, если стек пуст, или только по отдельному слову.
- Размеры: стек задачи оболочки, `mem_limit`, наибольшая длина строки,
  глубина истории, период уступки процессора (5.3) — после замеров на
  первом этапе.
- Порог долгого нажатия K1.
- Клавиша выхода из проверки платы: Esc (сейчас в проверке Esc очищает
  строку ввода) или свободная F11.
- Как `save` и пересборка обходятся со словами, созданными определяющими
  словами, со строками и с назначениями `is`, если доработка 2 из
  раздела 9 этого не покроет.
- Как показывать место ошибки в строке: знаком `^` под ним или инверсией;
  цвет не подходит — в 2-цветных режимах его нет.
- Мышь в первой версии не используется.
