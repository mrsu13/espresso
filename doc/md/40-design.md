# Архитектура

Этот документ описывает, каким будет Espresso: назначение, решения,
устройство программы, этапы работ и открытые вопросы. Он живой: каждое
изменение устройства, интерфейсов, решений или планов отражается здесь в
той же работе, а в конце документа ведётся журнал изменений.


## 1. Назначение

Espresso — самостоятельный терминал с языком Форт на плате LilyGO TTGO
VGA32 v1.4. К плате подключаются монитор VGA, клавиатура и мышь PS/2,
SD-карта и динамик; компьютер не нужен. Оболочка терминала — движок
Форта ff: пользователь набирает команды в редакторе строки, ff их
выполняет. Определения слов правятся в полноэкранном редакторе, который
запускает слово Форта. Тот же терминал доступен с ПК через
последовательный порт USB.


## 2. Оборудование

| Узел | Подключение |
|---|---|
| Процессор | ESP32-PICO-D4: два ядра Xtensa LX6 по 240 МГц, 520 КБ ОЗУ без PSRAM, 4 МБ флеш-памяти в корпусе |
| VGA | по 2 разряда на канал (первым указан старший), 64 цвета: красный — GPIO22 и GPIO21, зелёный — GPIO19 и GPIO18, синий — GPIO5 и GPIO4; строчный синхроимпульс — GPIO23, кадровый — GPIO15 |
| Клавиатура PS/2 | порт 0: CLK — GPIO33, DATA — GPIO32; оба порта обслуживает сопроцессор ULP |
| Мышь PS/2 | порт 1: CLK — GPIO26, DATA — GPIO27 |
| Звук | встроенный ЦАП, GPIO25 |
| SD-карта | шина SPI (выводы — в `esp::sd_card`), файловая система FAT в каталоге `/sdcard` |
| Кнопки | K1 — GPIO36 (только вход, внешняя подтяжка); K2 — сброс |
| USB | преобразователь USB — UART0, 115200 бод: прошивка, журнал ESP-IDF, терминал |


## 3. Главные решения

Решения приняты 2026-11-24 и 2026-11-26 по ответам на вопросы.

| Вопрос | Решение |
|---|---|
| Оболочка | движок ff (github.com/stoneagesoft/ff) — подмодуль git в `src/3rdparty/ff`; это сторонний код, его стиль не меняется |
| Ячейки ff | 32-разрядные (`FF_32BIT`), вещественные числа одинарной точности: блок плавающей точки ESP32 работает только с ними |
| Защита памяти | нет, как в настоящем ретрокомпьютере: неверный адрес в набранном коде может уронить плату; ff собирается без `FF_SAFE_MEM` (7.1) |
| Экран при запуске | 640 × 480, 4 цвета, шрифт Terminus 10 × 18: 64 × 26 знакомест, буфер кадра 75 КБ; режим меняется словом Форта |
| Язык | сообщения и справка ff — на русском и английском (переводы ff включены), по умолчанию английский, слово `lang!` переключает язык; ввод пока только латиницы, русский ввод — позже; кириллица в шрифте есть |
| Управление экраном | подмножество VT220 и альтернативный экран xterm в потоке вывода (6.2, 6.6) |
| Устройство терминала | пространство имён `esp::vt`: разборщик VT220 по автомату Пола Уильямса, модель экрана, разбор ввода и редактор строки (раздел 6) |
| Выделение | работает и в 2-цветных режимах: инверсией, подчёркиванием, жирным шрифтом; цвет его только дополняет |
| Последовательный порт | зеркало всего вывода и ввод с терминала ПК |
| Клавиши | байты последовательностей VT220, как от настоящего терминала: клавиатура PS/2 переводится в них; Форт получает байты словом `key`, а разобранные клавиши — словами `ekey` стандарта Forth 2012 (6.3, 7.5) |
| Редактор строки | история (хранится на SD-карте), дополнение слов по Tab в стиле bash, многострочные определения, клавиши в стиле Emacs |
| Полноэкранный редактор | текст определения даёт `see`; комментарии будут храниться вместе со словами (доработка ff); редактор работает на альтернативном экране (6.6) |
| После правки слова | слова, определённые после него, пересобираются, так что вызывающие слова получают новую версию |
| Переменные и массивы | значения сохраняются при пересборке и записываются словом `save` |
| Сохранение словаря | слово `save` пишет словарь на SD-карту; при запуске он загружается |
| Кнопка K1 | короткое нажатие прерывает выполнение, долгое заново ищет клавиатуру и мышь |
| Проверка платы | слово Форта `board-test`; выход — Esc (раздел 12) |
| История экрана | строки, ушедшие за верхний край основного экрана, хранятся в кольцевом буфере на 16 КБ — около 100–400 строк; на мониторе её листают Shift+PgUp и Shift+PgDn (6.7) |


## 4. Текущее состояние

Сделано к 2026-11-27:

- драйверы, взятые из FabGL и переработанные по руководству по стилю:
  `esp::vga` (VGA на 2, 4, 8, 16 и 64 цвета), `esp::gfx` (холст,
  примитивы, спрайты), `esp::ps2` (клавиатура и мышь на сопроцессоре
  ULP), `esp::sound` (звук через ЦАП или сигма-дельта-модулятор);
- шрифт Unicode Terminus 10 × 18 (`src/fonts`) и `esp::gfx::font`;
- `esp::sd_card`, `esp::button`, `esp::app`;
- проверка платы `esp::board_test`: цветные полосы, клавиатура, мышь,
  звук, проверка отсечения (F10) и смена видеорежимов (F12), в том числе
  1024 × 768; запускается словом Форта `board-test`, выход — Esc
  (раздел 12);
- руководство по стилю `doc/md/10-codestyle.md`;
- документация Doxygen (`doc/Doxyfile`, `doc/Makefile`): `make` в каталоге
  `doc` собирает HTML, `make pdf` — PDF через XeLaTeX; сторонний код
  (`src/3rdparty`) и файлы `INFO.md` в неё не входят;
- терминал (этап 1, раздел 13): разборщик `esp::vt::parser`, модель
  экрана `esp::vt::screen`, история экрана `esp::vt::scrollback`, перевод
  клавиш PS/2 в байты VT220 (`esp::vt::key_sequence()`) — с проверками на
  ПК (`test/run.sh`); рисование на VGA (`esp::vt::renderer`,
  `esp::vt::display`), ввод с PS/2 и UART0, копия вывода в UART0, журнал
  ESP-IDF через терминал (`esp::vt::terminal`), приостановка терминала на
  время проверки платы;
- редактор строки (этап 2): разборщик ввода `esp::vt::input_parser` и
  события клавиатуры `esp::vt::key_event`, история строк
  `esp::vt::line_history`, редактор строки `esp::vt::line_edit` — с
  проверками на ПК; файл истории на SD-карте
  (`esp::shell::history_file`); карта монтируется при запуске;
- движок ff (этап 3): подмодуль `src/3rdparty/ff` собирается своим
  `CMakeLists.txt` как подпроект — 32-разрядный, без `FF_SAFE_MEM`, с
  `FF_R_TRUSTED` и переводами ff (7.1);
- оболочка Форта `esp::shell::forth_shell` (7.3): цикл с редактором
  строки и историей, приглашение ff, знак `^` под ошибкой, освобождение
  временных строк; слова терминала (7.5), кроме `palette!`, `edit` и
  `save`; прерывание (7.6): Ctrl+C и короткое нажатие K1 прерывают код
  Форта, долгое нажатие K1 заново ищет клавиатуру и мышь (раздел 12);
  при запуске приложение выводит на терминал сведения о плате, а
  оболочка — заставку ff.

Слов `palette!`, `edit` и `save` и полноэкранного редактора ещё нет.

Оболочка и редактор рисуют только через терминал — последовательностями
ANSI в потоке вывода, а не прямо на холсте. Поэтому всё, что видно на
мониторе, так же выглядит и в терминале ПК.

### 5.3. Задачи и ядра

| Задача | Ядро | Что делает |
|---|---|---|
| Оболочка (новая) | 0 | цикл оболочки, выполнение Форта, полноэкранный редактор; стек с запасом (предварительно 16 КБ, уточнить замером): у главной задачи ESP-IDF всего 3,5 КБ. В ней работают и проверка платы (раздел 12), и файл истории на SD-карте; стек — 16 КБ |
| Клавиатура (новая) | 0 | переводит нажатия клавиш PS/2 в последовательности VT220 (6.3) и кладёт их в очередь ввода; Shift+PgUp и Shift+PgDn листают историю экрана (6.7); Ctrl+C сначала передаёт оболочке — пока выполняется код Форта, он прерывает код (7.6). Клавишу ждёт не дольше 100 мс, чтобы вовремя заметить приостановку терминала: тогда клавиш не берёт (раздел 12) |
| UART0 (новая) | 0 | кладёт байты, принятые с UART0, в ту же очередь ввода; места в ней не ждёт: если очередь полна, байт отбрасывается (6.4); Ctrl+C — как задача клавиатуры (7.6) |
| Главная (`app_main`) | 0 | запуск, затем опрос кнопки K1 каждые 10 мс: короткое нажатие прерывает код Форта (7.6), долгое заново ищет клавиатуру и мышь; во время проверки платы нажатие K1 через оболочку достаётся ей (раздел 12) |
| Мигание курсора | — | таймер FreeRTOS; его обратные вызовы выполняет задача таймеров FreeRTOS. Если терминал занят выводом, мигание пропускается: задача таймеров одна на всех и ждать не должна |
| Обработчик прерывания VGA | 1 (`esp::VIDEO_TASKS_CORE`) | готовит строки развёртки; задача, которая выполняет команды рисования драйверов с палитрой, работает на ядре 0 (`esp::core_usage::quiet_core()`) |
| Клавиатура и мышь PS/2 | любое | задачи драйверов, как сейчас, без привязки к ядру |
| Обработчик прерывания звука | 0 (`esp::core_usage::quiet_core()`) | как сейчас |

Экран терминала меняют задача оболочки и таймер курсора, поэтому
изменения экрана идут под мьютексом терминала.

Сторожевой таймер задач ESP-IDF следит за задачами простоя обоих ядер и
срабатывает, если задача простоя 5 с не получала процессор. Долгий цикл
Форта в задаче оболочки отнимал бы ядро 0 у его задачи простоя. Поэтому
обратный вызов `watchdog` движка ff (ff вызывает его через каждые 65 536
команд) смотрит на часы и раз в 100 мс (предварительно) отдаёт процессор
на один такт планировщика: `vTaskDelay(1)` — 1 мс при частоте
планировщика 1000 Гц, около 1 % скорости.


## 6. Терминал `esp::vt`

Терминал состоит из четырёх частей; оболочка и полноэкранный редактор
пользуются им через поток байтов.

| Часть | Что делает |
|---|---|
| `esp::vt::parser` | разбирает поток вывода (6.2) по автомату Пола Уильямса для VT220 и xterm (vt100.net) и собирает знаки из UTF-8; последовательности OSC, DCS и APC разбирает и пропускает, не накапливая |
| `esp::vt::screen` | выполняет разобранные последовательности над сеткой знакомест (6.1): курсор, вид текста, область прокрутки, альтернативный экран (6.6), история экрана (6.7) |
| `esp::vt::input_parser` | собирает из потока ввода события клавиатуры `esp::vt::key_event` — знаки и особые клавиши (6.3) |
| `esp::vt::line_edit` | редактор строки в духе readline с историей строк `esp::vt::line_history` (7.4) |

Путь данных: ввод → редактор строки → поток вывода → разборщик → экран.
Редактор строки выводит через `esp::vt::writer`: на плате это терминал,
в проверках на ПК — разборщик с экраном, по которому проверяется, что
видно.

Разборщик, модель экрана, разбор ввода и редактор строки не зависят от
ESP-IDF и проверяются на ПК: проверки лежат в каталоге `test` и
собираются обычным компилятором, без платы, с санитайзерами адресов и
неопределённого поведения; запуск — `test/run.sh`. Проверки пишут ESC как
`^[`.

### 6.1. Экран

Экран — сетка знакомест; её размер следует из видеорежима и шрифта
10 × 18: 64 × 26 при 640 × 480, 80 × 33 при 800 × 600, 102 × 42 при
1024 × 768. Знакоместо занимает 4 байта:

| Разряды | Что хранится |
|---|---|
| 0–15 | код знака Unicode |
| 16–19 | цвет текста — номер цвета ANSI, 0–15 |
| 20–23 | цвет фона — номер цвета ANSI, 0–15 |
| 24–31 | признаки: жирный, тусклый, курсив, подчёркнутый, инверсия, скрытый; два разряда в запасе |

UTF-8 в знакоместах не хранится: разборщик собирает из байтов UTF-8 код
знака, и знакоместо получает уже код. 16 разрядов хватает, потому что все
знаки шрифта — в основной плоскости Unicode (таблица `CODEPOINTS` шрифта —
из `std::uint16_t`, последний знак — U+FFFD); знак за её пределами шрифт
всё равно не нарисует, и он хранится как U+FFFD. Знаков двойной ширины и
комбинируемых знаков в шрифте нет: один знак — одно знакоместо.

Цвет хранится номером ANSI, а не цветом палитры, и сопоставляется с
палитрой видеорежима при рисовании: смена палитры или режима
перекрашивает экран. Признаки рисует сам вывод знаков: у
`esp::gfx::glyph_options` есть жирный, пониженная яркость, курсив,
подчёркивание, инверсия и пропуск знака.

Сеток две — основная и альтернативная (6.6), каждая около 6,5 КБ при
64 × 26. Основная сетка — главная копия экрана: по ней экран
перерисовывается после смены видеорежима, возврата с альтернативного
экрана или из проверки платы.

- Знакоместо рисуется знаком `esp::gfx::font` с заливкой фона; заново
  рисуются только изменившиеся знакоместа.
- Прокрутка на строку вверх — командой прокрутки холста (драйверы с
  палитрой меняют местами указатели строк, это быстро) и очисткой нижней
  строки.
- Курсор — инвертированное знакоместо; мигает раз в секунду (полсекунды
  виден, полсекунды скрыт), а при выводе сразу показывается на новом
  месте. Пока показ сдвинут в историю экрана, курсора нет.
- При 640 × 480 под 26 строками остаются 12 точек; они не используются.

### 6.2. Поток вывода

Всё, что выводит Форт, оболочка и редакторы, — поток байтов UTF-8.
Терминал разбирает его так:

| Байты | Действие |
|---|---|
| печатные знаки | знак в позиции курсора; в конце строки — перенос, внизу экрана — прокрутка |
| `0x07` (BEL) | короткий звук |
| `0x08` (BS) | курсор на знак влево |
| `0x09` (HT) | курсор к следующему столбцу, кратному 8 |
| `0x0A`–`0x0C` (LF, VT, FF) | курсор на строку вниз, у нижнего края области прокрутки — прокрутка; в начало строки курсор не возвращается, как в VT220 (одиночный LF терминал заранее заменяет на CR LF, 6.4) |
| `0x0D` (CR) | начало строки |
| `ESC 7` / `ESC 8` (DECSC / DECRC) | запомнить / вернуть положение курсора и вид текста |
| `ESC D` / `ESC M` (IND / RI) | курсор на строку вниз / вверх, у края области — прокрутка |
| `ESC E` (NEL) | начало следующей строки, у края области — прокрутка |
| `ESC c` (RIS) | полный сброс |
| `ESC [ n A` / `B` / `C` / `D` | курсор вверх / вниз / вправо / влево на n |
| `ESC [ n E` / `F` | курсор в начало n-й строки ниже / выше |
| `ESC [ n G` / `ESC [ n d` | курсор в столбец / строку n |
| `ESC [ r ; c H` или `f` | курсор в строку r, столбец c (с 1) |
| `ESC [ n J` | очистить экран: 0 — от курсора до конца, 1 — от начала до курсора, 2 — весь; 3 — стереть историю экрана (6.7), не трогая экран |
| `ESC [ n K` | очистить строку: 0, 1 и 2 — так же |
| `ESC [ n L` / `M` | вставить / удалить n строк |
| `ESC [ n @` / `P` / `X` | вставить / удалить / стереть n знаков |
| `ESC [ n S` / `T` | прокрутить область вверх / вниз на n строк |
| `ESC [ t ; b r` (DECSTBM) | область прокрутки — строки с t по b |
| `ESC [ s` / `u` | запомнить / вернуть положение курсора |
| `ESC [ … m` | вид текста: 0 — сброс; 1, 2, 3, 4, 7, 8 — жирный, тусклый, курсив, подчёркнутый, инверсия, скрытый; 22–28 — их отмена; 30–37, 90–97, `38;5;n`, `38;2;r;g;b` — цвет текста, 39 — по умолчанию; 40–47, 100–107, `48;5;n`, `48;2;r;g;b` — цвет фона, 49 — по умолчанию; цвета заменяются ближайшими из 16 цветов ANSI |
| `ESC [ ? 7 h` / `l` | перенос в конце строки включить / выключить |
| `ESC [ ? 25 h` / `l` | показать / скрыть курсор |
| `ESC [ ? 1049 h` / `l` | перейти на альтернативный экран / вернуться (6.6) |

Остальные последовательности — OSC, DCS, APC, выбор наборов знаков
VT220 — разбираются и пропускаются. Набор расширяется по мере
надобности; каждое расширение отражается в этой таблице.

### 6.3. Ввод

Ввод — один поток байтов в том виде, в каком его шлёт терминал VT220 или
xterm. С последовательного порта байты приходят уже в таком виде; нажатия
клавиш PS/2 (раскладка US, как сейчас) задача ввода переводит в те же
байты и кладёт в ту же очередь:

| Клавиша | Байты |
|---|---|
| знак | его байты UTF-8 (пока только латиница) |
| Ctrl+буква | управляющий знак 1–26 |
| Enter, Tab, Backspace, Esc | 13 (CR), 9 (HT), 127 (DEL), 27 (ESC) |
| Alt+клавиша | ESC, затем байты клавиши |
| ↑, ↓, →, ← | `ESC [ A`, `ESC [ B`, `ESC [ C`, `ESC [ D` |
| Home, End | `ESC [ H`, `ESC [ F` |
| Insert, Delete, PgUp, PgDn | `ESC [ 2 ~`, `ESC [ 3 ~`, `ESC [ 5 ~`, `ESC [ 6 ~` |
| F1–F4 | `ESC O P`, `ESC O Q`, `ESC O R`, `ESC O S` |
| F5–F12 | `ESC [ 15 ~`, `ESC [ 17 ~`, `ESC [ 18 ~`, `ESC [ 19 ~`, `ESC [ 20 ~`, `ESC [ 21 ~`, `ESC [ 23 ~`, `ESC [ 24 ~` |
| особая клавиша с Shift, Alt, Ctrl | второй параметр — 1 плюс признаки (Shift — 1, Alt — 2, Ctrl — 4): Ctrl+← — `ESC [ 1 ; 5 D`, Shift+F5 — `ESC [ 15 ; 2 ~`, Shift+F1 — `ESC [ 1 ; 2 P` |

Последовательности в потоке ввода разбирает `esp::vt::input_parser`
(раздел 6) — для редактора строки, полноэкранного редактора и слова
`ekey` (7.5); байт за байтом его кормит `esp::vt::terminal::read_key()`.
Он понимает и варианты, которые шлют другие терминалы ПК: Home и End как
`ESC [ 1 ~` и `ESC [ 4 ~` или как `ESC O H` и `ESC O F`, F1–F4 как
`ESC [ 11 ~` … `ESC [ 14 ~`. ESC, за которым 50 мс (предварительно)
ничего не пришло, — клавиша Esc; Backspace — и 127, и 8 (Ctrl+H). LF
сразу после CR пропускается: на Enter одни терминалы ПК шлют CR, другие
CR LF. Испорченная запись UTF-8 отбрасывается, незнакомые
последовательности — например, от мыши — пропускаются целиком.

Событие клавиатуры `esp::vt::key_event` — одно 32-разрядное число, то,
что вернёт `ekey`: код знака или номер особой клавиши
(`esp::vt::special_key`, с 0x110000) и признаки Shift (0x10000000),
Ctrl (0x20000000) и Alt (0x40000000) — значения те же, что в gforth.
Управляющие знаки — тоже знаки: Enter — CR, Tab — HT, Esc — ESC. Alt+знак
— знак с признаком Alt, Shift+Tab — HT с признаком Shift.

Ctrl+C обе задачи ввода сначала передают получателю прерывания (7.6).
Очередь ввода — 2 КБ: это ввод, набранный заранее, как в терминале Unix.
Места в ней задачи ввода не ждут — лишние байты отбрасываются, — а
принятое прерывание её сбрасывает.

### 6.4. Последовательный порт

Одиночный LF в потоке вывода терминал заменяет на CR LF, как терминал
Unix, — до разборщика и до UART0, поэтому монитор и терминал ПК получают
одно и то же. Весь поток вывода идёт ещё и в UART0, а байты, принятые с
UART0, поступают во ввод. Места в очереди ввода задача UART0 не ждёт:
если очередь полна, байт отбрасывается, как и лишнее нажатие клавиши
PS/2. Так Ctrl+C с терминала ПК доходит, даже когда программа не читает
ввод (7.6). Вставленный в терминал ПК текст не теряется, пока помещается
в очереди (2 КБ); приёмному буферу драйвера хватает 512 байтов — они
приходят на 115 200 бод за 44 мс, а задача UART0 забирает байты сразу.
Окно терминала ПК
должно быть не меньше экрана (64 × 26 при запуске), иначе полноэкранный
редактор в нём выглядит неправильно. Длинные строки редактор строки
переносит сам (7.4), поэтому в окне шире экрана они переносятся там же,
где на мониторе.

В UART0 пишет и журнал ESP-IDF. Строки, записанные мимо терминала, сбили
бы экран терминала ПК (положение курсора, альтернативный экран), поэтому
после запуска терминала журнал идёт через него (`esp_log_set_vprintf()`)
и попадает и на монитор, и в терминал ПК; уровень журнала тогда —
предупреждения. Сообщения ранней загрузки, до запуска терминала, идут в
UART0 как есть.

Альтернативный экран (6.6) — расширение xterm, а не VT220: его понимают
xterm-совместимые терминалы ПК, в окне которых работают picocom, tio или
`idf.py monitor`.

### 6.5. Видеорежимы и палитра

При запуске — 640 × 480, 4 цвета (`esp::vga::vga4_controller`). Слово
Форта переключает видеорежим на один из проверенных на плате: 640 × 480
с 16, 8, 4 и 2 цветами, 800 × 600 с 4 и 2 цветами, 1024 × 768 с 2
цветами в двух развёртках. Видеоконтроллер прежнего режима
останавливается (`end()`) и уничтожается, как в проверке платы; размер
сетки меняется, экран очищается.

Палитры видеорежимов (`esp::vt::display`): при 16 цветах — 16 цветов
ANSI в цветах VGA, при 8 — первые восемь из них, при 4 — чёрный фон,
светло-серый текст, ярко-жёлтый для приглашения и выделения, красный для
ошибок (предложение; позже палитра будет задаваться словом), при 2 —
чёрный и светло-серый. Цвета из последовательностей ANSI рисование
заменяет ближайшими цветами палитры. Если у знака цвет текста и цвет фона
разные, а в палитре они совпали — например, зелёный текст на чёрном в
4-цветном режиме становится чёрным, — текст рисуется цветом по умолчанию
(а на таком фоне — фоном по умолчанию), чтобы не пропасть.

В 2-цветных режимах (640 × 480, 800 × 600 и 1024 × 768) цвет ничего не
различает, поэтому выделение в оболочке и редакторах делается признаками
— инверсией, подчёркиванием, жирным шрифтом, — а цвет его только
дополняет.

### 6.6. Альтернативный экран

`ESC [ ? 1049 h` запоминает курсор и вид текста (как `ESC 7`),
переключает вывод на альтернативную сетку и очищает её. `ESC [ ? 1049 l`
возвращает основную сетку, курсор и вид текста и перерисовывает экран по
основной сетке: буфер кадра у VGA один, а перерисовка 64 × 26 знакомест
займёт, по оценке, десятки миллисекунд. У каждой сетки — свои курсор, вид
текста и область прокрутки. Обе сетки выделяются при включении
видеорежима, чтобы переход на альтернативный экран не срывался из-за
нехватки памяти.

Полноэкранный редактор работает на альтернативном экране: после выхода
из него экран оболочки возвращается таким, каким был, — и на мониторе, и
в терминале ПК.

### 6.7. История экрана

Строки, которые уходят за верхний край основного экрана, когда перевод
строки прокручивает его целиком, попадают в историю экрана
(`esp::vt::scrollback`). Строки, стёртые, удалённые (`ESC [ M`) или
прокрученные внутри области прокрутки, в неё не попадают; у
альтернативного экрана истории нет, как в xterm.

- Строка хранится только до последнего непустого знакоместа: пустые
  знакоместа с видом текста по умолчанию в конце строки отбрасываются.
  Знакоместа лежат подряд в кольцевом буфере на 4096 знакомест (16 КБ),
  начало и длина каждой строки — в списке на 512 строк (2 КБ). Когда
  места нет, уходят самые старые строки. Строки вывода оболочки и Форта
  обычно короткие, поэтому в буфере помещается около 100–400 строк.
- Память выделяется вместе с сетками экрана. При смене видеорежима
  история очищается: её строки рассчитаны на прежнюю ширину.
- На мониторе историю листают Shift+PgUp и Shift+PgDn, на полэкрана за
  нажатие. На основном экране эти клавиши забирает терминал, программам
  они не достаются; на альтернативном экране они идут программе. Любой
  вывод и любая другая клавиша возвращают экран вниз, к текущим строкам.
- У терминала ПК история своя, в его окне, поэтому история экрана нужна
  только монитору.


## 7. Оболочка `esp::shell`

### 7.1. Движок ff

ff — библиотека на C17. Всё состояние Форта хранится в экземпляре
`ff_t`; общая для всех экземпляров только таблица встроенных слов,
которую ff строит при первом `ff_new()`. Сама ff ничего не печатает и
не читает: вывод, диагностика, файлы и пределы — это обратные вызовы и
поля `ff_platform_t`, которые даёт хост (7.2). Текст выполняется
функцией `ff_eval()`; начатое в одном вызове (определение, комментарий)
продолжается в следующем.

- Исходники — подмодуль git `src/3rdparty/ff`. Автоматический сбор
  каталогов компонента `src` (`cmake/tools.cmake`) этот каталог
  пропускает: иначе в сборку попали бы тесты, примеры и фаззер ff, а в
  пути заголовков — его сторонние библиотеки. В документацию Doxygen ff
  тоже не входит: `doc/Doxyfile` исключает весь `src/3rdparty`.
- ff собирается своим `CMakeLists.txt` как подпроект CMake:
  `add_subdirectory()` в `src/CMakeLists.txt` делает статическую
  библиотеку `ff::ff`, и компонент `src` с ней компонуется. Espresso не
  ведёт свой список файлов ff. Для этого ff доработан (доработка 5 из
  раздела 9): пути он считает от своего каталога, а не от каталога
  проекта-хозяина; подпроект не трогает тип сборки хозяина и не
  добавляет правил установки и pkg-config (параметр `FF_INSTALL`
  выключен); 32-разрядные ячейки — параметр CMake `FF_32BIT`.
- Параметры ff Espresso задаёт через кэш CMake до `add_subdirectory()`:
  ff объявляет их через `option()`, и значение из кэша сильнее значения
  по умолчанию. ff собирается с флагами ESP-IDF и своими `-Wall -Wextra
  -Werror` — без предупреждений.
- Пути заголовков ff и Espresso не смешиваются: у обоих своя `utf8.h`,
  и копии различаются. Espresso видит только каталог `src` ff с его
  открытыми заголовками (`ff.h`, `ff_platform.h`) и созданный при
  настройке `ff_version.h`; сторонние библиотеки ff остаются внутри ff.
  Заголовок `ff.h` есть и у FatFs из ESP-IDF, и `esp_vfs_fat.h`
  включает его по тому же имени, поэтому Espresso включает главный
  заголовок ff как `<ff/src/ff.h>` — по пути от `src/3rdparty`.
- Параметры сборки:

| Параметр | Значение | Почему |
|---|---|---|
| `FF_32BIT` | включён | 32-разрядные ячейки и вещественные числа одинарной точности (раздел 3) |
| `FF_SAFE_MEM` | выключен | как в настоящем ретрокомпьютере: адреса не проверяются, и неверный адрес в набранном коде может уронить плату; зато Форт быстрее — по README ff, на 10–20 % |
| `FF_R_TRUSTED` | включён | по той же причине: ff не проверяет стек возвратов там, где правильный код его не нарушит, — `i` или `j` вне цикла остаются без проверки; около 5 % скорости на циклах |
| `FF_WITH_SYSTEM` | выключен | слову `system` на плате нечего запускать |
| `FF_WITH_FILES` | включён | файловые слова и `load` — для файлов на SD-карте через стандартную библиотеку C и VFS ESP-IDF |
| `FF_WITH_TR` | включён | сообщения и справка ff на русском и английском (раздел 3) |
| `FF_BUILD_SHARED` | выключен | на плате нужна только статическая библиотека |
| `FF_PAD_INIT_SIZE` | 2048 | кусок временной области строк — 2 КБ, а не 32 КБ: столько был бы половиной памяти Форта (7.3) |
| `FF_DICT_ARENA_SLAB` | 4096 | кусок памяти слов — 4 КБ, а не 64 КБ: такой кусок занял бы всю память Форта, и одним куском его в куче нет (доработка 8 из раздела 9) |

### 7.2. Обратные вызовы ff

| Поле `ff_platform_t` | Что делает в Espresso |
|---|---|
| `vprintf` | форматирует текст и отдаёт его в поток вывода терминала; короткий текст — на стеке, длинный — во временном буфере в куче |
| `vtracef` | трассировку и предупреждения ff — с начала строки экрана; предупреждение ярко-жёлтым и со словом «Warning:» («Предупреждение:») на языке движка; ошибки ff сюда не передаёт, их даёт `ff_strerror()` |
| `watchdog` | раз в 100 мс отдаёт процессор на такт планировщика (5.3); пока стоит отметка прерывания, останавливает ff (7.6); `watchdog_interval` — по умолчанию, 65 536 команд |
| `deny` | ничего не запрещает |
| `open_file` | относительные пути отсчитываются от `/sdcard`; без SD-карты — ошибка |
| `run_command` | не нужен: слова `system` нет |
| `mem_limit` | предел памяти слов и строк Форта (сверх него — ошибка −8), чтобы её хватило экрану; предварительно 64 КБ, уточнить замером |
| `lang` | не задан — английский; слово ff `lang!` переключает на русский, `lang@` возвращает язык, `.langs` выводит список |

### 7.3. Цикл оболочки

Оболочка — `esp::shell::forth_shell`, в своей задаче (5.3).

1. Создать ff (`ff_new()`) и зарегистрировать слова терминала (7.5).
2. Вывести заставку: `ff_banner()` и версию ff; сведения о плате и
   версию Espresso приложение выводит раньше.
3. Загрузить словарь с SD-карты (7.7) — с этапа 5.
4. Повторять: показать приглашение `ff_prompt()` ярко-жёлтым, прочитать
   строку редактором строки, добавить её в историю и выполнить
   `ff_eval()`. Приглашение всегда начинается с начала строки экрана:
   если вывод кончился не переводом строки, оболочка его добавляет.
5. При ошибке отметить её место знаком `^` (`ff_err_pos()`) и вывести
   сообщение `ff_strerror()` красным, со словом «Error:» («Ошибка:»).
   Знак виден и в 2-цветных режимах, и в терминале ПК, а инверсию
   пришлось бы рисовать, выводя строку заново. Если после строки ничего
   не выведено и она уместилась в одну строку экрана, знак встаёт прямо
   под ней; иначе строка выводится заново — сколько её помещается в
   строку экрана вокруг ошибки, — и знак встаёт под ней. Прерывание
   (7.6) — не ошибка: о нём ярко-жёлтое «Interrupted.» («Прервано.»)
   без «Error:», тоже со знаком `^`.

Ошибка не очищает стек: ff оставляет на нём то, что было, и `clear`
убирает это, когда нужно.

Приглашение ff показывает, что определение ещё не закрыто: `▶` — обычное,
`:▶` — внутри определения, `(▶` — внутри комментария. Так работают
многострочные определения: каждая строка выполняется сразу, а ff
продолжает открытое определение со следующей строки. Если в строке
посреди определения ошибка, ff сам убирает недописанное определение.

Строки, набранные вне определений, и строки, которые кладут на стек
`accept` и `parse`, ff держит во временной области. Это не кольцо, как
в классическом Форте: область растёт кусками по 32 КБ, которые
считаются в предел памяти, и остаётся занятой, пока хост её не
освободит (`ff_release_strings()`) или `abort` не сбросит движок. Поэтому
оболочка освобождает её после каждой строки, набранной вне определения,
если стек пуст: тогда ни на стеке, ни в незаконченном определении
адресов этих строк нет. Строка, адрес которой положили в переменную,
после этого становится недействительной; проверки адресов нет, и обращение
к ней может уронить плату. Кусок в 32 КБ — половина памяти Форта (раздел
10), поэтому размер куска в ff задаётся при сборке (доработка 6 из
раздела 9), и на плате он 2 КБ (`FF_PAD_INIT_SIZE`).

### 7.4. Редактор строки

Редактор строки — `esp::vt::line_edit` (раздел 6). Эхо, перерисовку и
движение курсора он выводит только байтами в поток терминала, поэтому
одинаково работает на мониторе и в терминале ПК. Вывод на одну клавишу
он копит в буфере и отдаёт терминалу одним куском. Клавиши:

| Действие | Клавиши |
|---|---|
| на знак влево / вправо | ← / →, Ctrl+B / Ctrl+F |
| на слово влево / вправо | Ctrl+← / Ctrl+→, Alt+B / Alt+F |
| в начало / конец строки | Home / End, Ctrl+A / Ctrl+E |
| удалить знак слева / под курсором | Backspace, Ctrl+H / Delete, Ctrl+D |
| удалить слово слева / справа | Ctrl+W, Alt+Backspace / Alt+D |
| удалить до конца / от начала строки | Ctrl+K / Ctrl+U |
| вставить последнее удалённое | Ctrl+Y |
| предыдущая / следующая строка истории | ↑ / ↓, Ctrl+P / Ctrl+N |
| поиск по истории назад | Ctrl+R |
| дополнить слово | Tab |
| выполнить строку | Enter |
| отменить строку: она остаётся на экране с `^C`, начинается новая | Ctrl+C |
| очистить экран и вывести строку заново | Ctrl+L |

- Слово — знаки между пробелами, как у Форта: по ним идут движение и
  удаление по словам.
- Tab при одном варианте дополняет слово целиком и ставит за ним пробел,
  при нескольких — до общего начала. Если дополнять нечего, звучит
  звонок, а следующий Tab выводит список вариантов, как в readline.
  Варианты — имена слов словаря без учёта регистра латиницы, как их ищет
  `ff_find()`; перебирать слова из C ff пока не умеет (доработка 3 из
  раздела 9), поэтому до неё Tab только звенит. Подсказка серым
  после курсора не подходит: в 2-цветных режимах её не отличить от
  набранного текста.
- Курсор, удаление и движение по словам идут по целым знакам UTF-8, а не
  по байтам: иначе двухбайтовый знак кириллицы разрезался бы.
- Длинная строка переносится на следующие строки экрана. Переносит её сам
  редактор — CR LF после последнего столбца, а не перенос терминала, —
  поэтому в окне терминала ПК шире экрана строка переносится там же, где
  на мониторе. Приглашение начинается там, где стоит курсор: у оболочки —
  в начале строки экрана, у слова `accept` — после вопроса программы
  (7.5); строка переносится по тем же столбцам экрана. Наибольшая длина
  строки — 256 байт (предварительно); знак сверх неё не вставляется,
  звучит звонок.
- История строк `esp::vt::line_history` — последние строки в кольцевом
  буфере на 8 КБ со списком на 256 строк, около 100 строк обычной длины;
  пустые строки, строки из одних пробелов и повторы предыдущей в неё не
  попадают. ↑ и ↓ показывают строки истории; набранная строка
  запоминается, и ↓ после самой новой строки истории возвращает её.
  Правка показанной строки истории при следующем шаге пропадает: в
  истории строка остаётся, какой была, а выполненная правленая строка
  добавляется как новая.
- Поиск Ctrl+R — как в bash: приглашение `(reverse-i-search)` со строкой
  поиска, за ним найденная строка. Знаки дописываются в строку поиска,
  Ctrl+R ищет строку старше, Backspace стирает знак поиска, Enter
  выполняет найденную строку, Ctrl+G и Esc возвращают строку, какой она
  была до поиска; любая другая клавиша кончает поиск и правит найденную
  строку. Если строки нет, приглашение говорит `failed` и звучит звонок.
- Строки в историю добавляет оболочка, и каждую новую строку истории она
  дописывает в файл `/sdcard/history.ff` (раздел 11,
  `esp::shell::history_file`). Файл открывается и закрывается на каждую
  строку, так что выполненная строка не теряется и при выключении платы.
  При запуске история читается из файла; когда он становится вдвое
  больше истории, он переписывается её строками.
- Без SD-карты история живёт только в памяти. Если записать в файл не
  удалось — например, карту вынули, — журнал один раз предупреждает об
  этом, и дальше история тоже живёт только в памяти. Карта монтируется
  при запуске; вставленную позже программа не видит до перезапуска.

### 7.5. Слова терминала

Хост добавляет в ff свои слова (`ff_register()`); у каждого — справка
для `man` (пока на английском). Имена — предложение:

| Слово | Стек | Что делает |
|---|---|---|
| `key` | ( -- c ) | ждёт байт ввода и кладёт его (6.3): у знака кириллицы таких байтов два, у особой клавиши — целая последовательность |
| `key?` | ( -- f ) | есть ли байт в очереди ввода |
| `ekey` | ( -- x ) | ждёт событие клавиатуры: собирает знак UTF-8 или последовательность особой клавиши в одно значение — код знака или номер особой клавиши от `0x110000` с признаками Shift, Alt и Ctrl в старших разрядах, как `esp::vt::key_event` (6.3) |
| `ekey?` | ( -- f ) | есть ли событие клавиатуры |
| `ekey>char` | ( x -- c f ) | f — истина, если x — знак, и тогда c — его код; иначе c — это x |
| `ekey>fkey` | ( x -- u f ) | f — истина, если x — особая клавиша, и тогда u — её номер с признаками; иначе u — это x |
| `k-left` … `k-f12`, `k-shift-mask`, `k-ctrl-mask`, `k-alt-mask` | ( -- u ) | номера особых клавиш и признаки — для сравнения с результатом `ekey>fkey` |
| `accept` | ( -- s ) | читает строку через редактор строки и кладёт её адрес (строка — во временной области ff, 7.3) |
| `page` | ( -- ) | очищает экран |
| `at-xy` | ( x y -- ) | ставит курсор в столбец x, строку y |
| `fg`, `bg` | ( n -- ) | цвет текста / фона — номер цвета ANSI, 0–15 (6.1) |
| `ms` | ( n -- ) | пауза на n мс |
| `beep` | ( -- ) | короткий звук |
| `tone` | ( частота мс -- ) | звук заданной частоты |
| `video-mode` | ( n -- ) | переключает видеорежим (6.5) |
| `palette!` | ( r g b n -- ) | задаёт цвет палитры |
| `edit` | ( "имя" -- ) | открывает определение в полноэкранном редакторе |
| `save` | ( -- ) | записывает словарь на SD-карту |
| `board-test` | ( -- ) | запускает проверку платы |

`page`, `at-xy`, `fg` и `bg` выводят последовательности ANSI, поэтому
действуют и на экране, и в терминале ПК.

`ekey`, `ekey?`, `ekey>char`, `ekey>fkey` и константы клавиш — слова
стандарта Forth 2012 (расширение Facility): `k-left`, `k-right`, `k-up`,
`k-down`, `k-home`, `k-end`, `k-prior`, `k-next`, `k-insert`,
`k-delete`, `k-f1` … `k-f12`.

Сделаны (этап 3) все слова таблицы, кроме `palette!`, `edit` и `save`;
их добавляет `esp::shell::terminal_words`, у каждого справка для `man` на
английском и русском. Подробности:

- Для `ekey>char` знак — только знак без клавиш-модификаторов, в том
  числе управляющий (Enter, Tab, Ctrl+A). Всё остальное — особые клавиши
  и знаки с Alt или Shift+Tab — для `ekey>fkey`, так что каждое событие —
  что-то одно.
- `key?` и `ekey?` говорят, есть ли в очереди хоть один байт ввода:
  знак UTF-8 и особая клавиша — несколько байтов одного события.
- `accept` набирает строку своим редактором строки со своей историей —
  не историей оболочки — с того места, где стоит курсор, после вопроса,
  который вывела программа. Ctrl+C и K1 прерывают программу (7.6), а
  набранное остаётся на экране с `^C`, как при отмене строки.
- `beep` выводит BEL: звонок звучит и на плате, и в терминале ПК. `tone`
  подаёт прямоугольную волну и ждёт, пока она отзвучит, — так ноты
  мелодии идут одна за другой; генератор звука при этом занят под
  мьютексом терминала, как для звонка. Прерывание обрывает звук.
- Неверный аргумент — цвет не 0–15, нет такого видеорежима, частота не
  1–20000 Гц, пауза меньше нуля — ошибка −24, неверный числовой
  аргумент по стандарту Forth.

### 7.6. Прерывание

Ctrl+C (с клавиатуры или из терминала ПК) и короткое нажатие K1
прерывают выполняющийся код Форта: задача ввода (для K1 — главная
задача) вызывает `ff_request_abort()`. ff останавливается на ближайшем
переходе или вызове слова, и `ff_eval()` возвращает ошибку
`FF_ERR_ABORTED`, которую не перехватывает никакой `catch`; оболочка
сообщает о прерывании и выводит приглашение.

Сделано на этапе 3:

- Задачи ввода передают Ctrl+C получателю прерывания терминала
  (`esp::vt::interrupt_handler`) — оболочке; принятый Ctrl+C в ввод не
  попадает. K1 подаёт прерывание через терминал так же
  (`esp::vt::terminal::interrupt()`).
- Принятое прерывание сбрасывает непрочитанный ввод, как Ctrl+C в
  терминале Unix: клавиши, нажатые, пока код выполнялся, ни ему, ни
  следующему приглашению не достаются. Терминал опустошает очередь
  ввода, а событие клавиатуры, начатое до сброса, разборщик ввода
  отбрасывает. Задачи ввода места в очереди не ждут (6.4), поэтому Ctrl+C
  не застревает за набранным заранее вводом.
- Слова терминала, которые ждут (`key`, `ekey`, `accept`, `ms`, `tone`,
  `board-test`), ждут шагами по 50 мс и между шагами проверяют отметку
  прерывания. Заметив её, слово бросает исключение −28 — прерывание
  пользователем по стандарту Forth; его ff тоже не даёт перехватить, и
  `ff_eval()` возвращает `FF_ERR_ABORTED`. Слово не может вернуться и
  ждать, пока ff остановится на следующем слове: оно может быть
  последним в строке.
- `accept` при прерывании отменяет строку, как Ctrl+C в оболочке:
  набранное остаётся на экране с `^C`. `tone` обрывает звук.
- О прерывании оболочка сообщает ярко-жёлтым «Interrupted.»
  («Прервано.») без «Error:», со знаком `^` под словом, на котором код
  остановился. Сообщение одно, ждал ли код или считал: у ff после
  `ff_request_abort()` своё сообщение, с числом выполненных операций.
- Просьбу, пришедшую между вызовами, ff сбрасывает в начале следующего
  вызова. Поэтому оболочка отмечает, когда выполняется код Форта, и
  Ctrl+C и K1 прерывают только тогда; в остальное время Ctrl+C —
  обычная клавиша: в редакторе строки она отменяет строку, а K1
  отвечает звонком. Если Ctrl+C пришёл в самом начале строки, раньше,
  чем `ff_eval()` сбросил старые просьбы, ff всё равно останавливается:
  его сторожевой обратный вызов (7.2) видит отметку прерывания.

Полноэкранный редактор (этап 6), хотя его и запускает слово `edit`, на
время своей работы снимает эту отметку: в нём Ctrl+C — обычная клавиша,
а K1 не прерывает. Пересборку (8.3) прервать можно.

### 7.7. Сохранение и загрузка словаря

- `save` записывает в `/sdcard/espresso.ff` все слова, созданные кодом
  Форта (встроенные слова ff и слова терминала в файл не попадают), по
  порядку определения: текст каждого даёт `see` вместе с комментариями.
  После определений идёт код, который восстанавливает значения
  переменных и массивов. Прежний файл переименовывается в
  `espresso.bak`.
- При запуске оболочка загружает `/sdcard/espresso.ff` (`ff_load()`),
  если он есть; ошибки выводятся, но оболочка запускается в любом случае.
- Без SD-карты `save` сообщает об ошибке, словарь не загружается, история
  живёт только в памяти.


## 8. Полноэкранный редактор `esp::editor`

### 8.1. Вызов и экран

`edit имя` открывает текст определения, который даёт `see` вместе с
хранимыми комментариями. Для нового имени открывается заготовка
`: имя ;`. Экран редактора при 64 × 26:

- строка 1 — заголовок в инверсии: имя слова, признак изменений;
- строки 2–25 — текст;
- строка 26 — в инверсии: подсказка по клавишам, сообщения и ошибки.

Редактор работает на альтернативном экране (6.6) и рисует через поток
вывода терминала, поэтому работает и в терминале ПК. Текст он
прокручивает областью прокрутки и вставкой и удалением строк (6.2) — это
дёшево и на последовательной линии; клавиши разбирает
`esp::vt::input_parser`.

### 8.2. Клавиши

Движение по строке и удаление — как в редакторе строки (7.4); кроме
того:

| Действие | Клавиши |
|---|---|
| на строку вверх / вниз | ↑ / ↓, Ctrl+P / Ctrl+N |
| на экран вверх / вниз | PgUp / PgDn |
| в начало / конец текста | Ctrl+Home / Ctrl+End |
| новая строка с отступом предыдущей | Enter |
| отступ на 4 пробела | Tab |
| проверить, сохранить и пересобрать (8.3) | Ctrl+S или F2 (для терминалов ПК, которые оставляют Ctrl+S себе) |
| выйти; если текст изменён и не сохранён — спросить | Esc |

### 8.3. Сохранение и пересборка

ff, как классический Форт, при новом определении того же имени оставляет
слова, скомпилированные раньше, со старой версией. Чтобы они получили
новую, редактор пересобирает всё, что определено после правленого слова;
`forget` в ff как раз убирает слово вместе со всеми словами после него.

1. Запоминает текст (по `see`, с комментариями) всех слов, определённых
   после старой версии, по порядку, и значения переменных и массивов —
   этих слов и самого правленого, если оно переменная или массив.
2. Компилирует новый текст как новое определение. При ошибке ff сам
   убирает недописанное определение, словарь остаётся прежним, курсор
   встаёт на место ошибки (`ff_err_line()`, `ff_err_pos()`), сообщение —
   в нижней строке.
3. Забывает старую версию (`forget`); с ней уходят все слова после неё,
   в том числе пробное определение из шага 2.
4. Выполняет новый текст, затем запомненные тексты по порядку и
   восстанавливает значения (массива — если его размер не изменился).
5. Если какое-то слово не компилируется, пересборка останавливается, а
   это слово открывается в редакторе; слова до него уже пересобраны.

Ограничения:

- ff не забывает слово, пока выполняется оно или любое слово после него.
  Если `edit` вызван не из командной строки, а из такого слова,
  пересборка невозможна, и редактор сообщает об этом.
- Новый текст выполняется дважды (шаги 2 и 4), поэтому в нём должно
  быть только определение: код вне определения выполнился бы два раза.
- Пересборка верна, только если текст `see` компилируется обратно в то
  же самое слово для всех видов слов (раздел 9).


## 9. Доработки ff

Делаются в репозитории ff и попадают в Espresso обновлением подмодуля.

1. Комментарии хранятся вместе со словом, и `see` выводит их на своих
   местах.
2. Текст `see` компилируется обратно в то же слово для всех видов слов,
   и это проверяют тесты ff. Сейчас это не так для переменных: `see`
   выводит `create x ( 1 cell reserved )`, а такой текст создаёт слово
   без памяти. Не так и для `defer` (назначение `' y is x` стоит в
   комментарии) и для слов, созданных через `does>`: они выводятся
   описанием, а не кодом.
3. Интерфейс C для словаря: перебор слов по порядку определения (для
   дополнения, `save` и пересборки), вид слова, адрес и размер данных
   переменных и массивов (для их значений).
4. 32-разрядная сборка: компилятор Xtensa из ESP-IDF с `FF_32BIT` без
   предупреждений — уже так (2026-11-26); остались тесты ff в
   32-разрядной сборке на ПК (`-m32`).
5. Сделано: `CMakeLists.txt` ff подключается через `add_subdirectory()`
   (7.1). Пути — от каталога ff (`PROJECT_SOURCE_DIR`); подпроект не
   трогает тип сборки хозяина и без `FF_INSTALL` не добавляет правил
   установки, пакета CMake и pkg-config; `FF_32BIT` — параметр CMake.
   Самостоятельная сборка ff не изменилась, его проверки проходят.
6. Сделано: размер куска временной области строк задаётся при сборке —
   параметр CMake `FF_PAD_INIT_SIZE` (по умолчанию 32 КБ). На плате 32 КБ
   были бы половиной памяти Форта, а строкам, набранным в оболочке,
   хватает 2 КБ (7.3).
7. Исправлено: комментарий `( … )`, у которого `)` — последний байт
   текста для `ff_eval()`, ff считал незакрытым, и комментарий глотал
   следующие строки. Строка от редактора строки приходит без перевода
   строки, так что `( заметка )` в оболочке попадал как раз на это.
   Проверка — случай `047_comment_close` в проверках ff.
8. Сделано: размер куска памяти слов задаётся при сборке — параметр
   CMake `FF_DICT_ARENA_SLAB` (по умолчанию 64 КБ); на плате — 4 КБ.
   Код слов и данные переменных ff берёт из кусков, и первое же
   определение открывает кусок; каждый кусок целиком считается в предел
   памяти, а у предела его урезают до того, что осталось. С куском в
   64 КБ первое определение падало: `malloc` не находил в куче столько
   одним куском (`: spin begin again ;` — «Out of memory allocating 256
   bytes» на `again`, первом слове, которое компилирует код). А если бы
   и нашёл, кусок, урезанный до предела в 64 КБ, занял бы всю память
   Форта, и следующее определение уже не поместилось бы. С кусками по
   4 КБ в предел помещаются сотни слов.


## 10. Память

ОЗУ без PSRAM — около 520 КБ, из них свободной кучи после запуска ESP-IDF
заметно меньше; точные цифры — замером на первом этапе.

| Что | Объём |
|---|---|
| буфер кадра 640 × 480, 4 цвета | 75 КБ |
| очередь команд рисования VGA (1024 команды) | ≈ 16 КБ |
| дескрипторы DMA и строки развёртки | ≈ 15 КБ |
| две сетки знакомест 64 × 26: основная и альтернативная (6.6) | 13 КБ |
| история экрана: 4096 знакомест и список на 512 строк (6.7) | 18 КБ |
| стек задачи оболочки | 16 КБ (предварительно) |
| слова и строки Форта (`mem_limit`) | 64 КБ (предварительно) |
| история строк: кольцевой буфер и список на 256 строк (7.4) | 9 КБ |
| редактор строки: набираемая, сохранённая и удалённая строки, поиск, буфер вывода | ≈ 2 КБ |
| текст в полноэкранном редакторе и при пересборке | до ≈ 8 КБ |
| очередь ввода (6.3) | 2 КБ |
| буферы UART0: приём и передача (6.4) | 2,5 КБ |
| звук, PS/2, SD-карта | несколько КБ |

Видеорежим с большим буфером кадра (640 × 480 при 16 цветах — 150 КБ)
оставляет Форту меньше памяти. С этого режима начинает проверка платы:
на её время терминал освобождает свой буфер кадра, а сетки знакомест и
история экрана (31 КБ) остаются. Если памяти не хватит, видеоконтроллер
уменьшит высоту изображения.

Флеш-память: прошивка с ff занимает около 700 КБ из 1 МБ раздела
приложения; сам ff со справкой на двух языках — около 230 КБ. Если
прошивка перерастёт раздел, его можно увеличить: у ESP32-PICO-D4 4 МБ
флеш-памяти.

## 12. Кнопка K1 и проверка платы

- Короткое нажатие K1 — кнопку отпустили раньше чем через 1 с —
  прерывает выполнение Форта, как Ctrl+C (7.6); если прерывать нечего,
  оно отвечает звонком.
- Долгое нажатие — кнопку держат 1 с (предварительно) — сразу отвечает
  звонком и заново ищет клавиатуру и мышь, подключённые после запуска;
  сброс каждого устройства занимает до двух секунд. Короткое оно или
  долгое, становится ясно, только когда кнопку отпустили или продержали
  порог, поэтому прерывание — по отпусканию.
- Во время проверки платы нажатие K1 сразу достаётся ей.
- `board-test` приостанавливает терминал (`esp::vt::terminal::suspend()`)
  и запускает проверку платы `esp::board_test` со всеми её клавишами
  (F1–F10, F12) и мышью. Терминал отдаёт ей монитор, клавиатуру PS/2 и
  генератор звука:
  - видеоконтроллер терминала останавливается и освобождается — двум
    буферам кадра памяти не хватит;
  - задача клавиатуры перестаёт брать клавиши; `suspend()` возвращает
    управление, когда она остановилась, поэтому клавиши, нажатые до
    этого, ещё для терминала, а после — для проверки;
  - генератор звука у них общий, терминала: двум генераторам не работать
    сразу — оба выводят звук через I2S0 и ЦАП. Одним генератором нельзя
    пользоваться из двух задач сразу, поэтому терминал на это время
    звонок не подаёт.
- Проверка работает в задаче оболочки: оболочка опрашивает её каждые
  10 мс и передаёт ей нажатия K1 — главная задача только отмечает их.
  Контроллер PS/2 проверка не перезапускает: `begin()` создал бы
  клавиатуру заново, и у задачи клавиатуры терминала осталась бы
  уничтоженная.
- Вывод и журнал за время проверки идут в модель экрана и в UART0, ввод с
  UART0 пропускается.
- Выход — Esc на клавиатуре PS/2 или одиночный ESC с терминала ПК (за ним
  50 мс ничего не пришло). Проверка останавливает свой видеоконтроллер и
  отпускает мышь, а терминал (`resume()`) включает свой видеорежим и
  перерисовывает экран по сетке знакомест — с тем, что было выведено за
  время проверки.


## 13. Этапы работ

Терминал делается раньше Форта: он от Форта не зависит, а до ff его
ведёт временная тестовая оболочка.

1. Терминал `esp::vt`: разборщик, экран с альтернативным экраном и
   историей экрана, рисование через `esp::gfx`, курсор, ввод (клавиатура PS/2 →
   последовательности VT220, последовательный порт), зеркало вывода,
   журнал ESP-IDF через терминал (6.4). Временная тестовая оболочка: эхо
   и несколько команд — очистка экрана, проверка признаков и цветов,
   смена видеорежима, текст проверки VT, `board-test`; потом ff заменяет
   её команды. Проверки разборщика и экрана на ПК (раздел 6).
2. Редактор строки `esp::vt::line_edit`: клавиши, курсор по знакам UTF-8,
   дополнение в стиле bash по постоянному списку слов, история на
   SD-карте.
3. ff на ESP32: подмодуль, сборка (7.1), оболочка на терминале — задача
   оболочки, цикл, многострочные определения, слова терминала,
   прерывание (Ctrl+C, K1); замеры памяти и скорости.
4. Доработки ff (раздел 9), первой — интерфейс C для словаря: к нему
   подключается дополнение.
5. `save` и загрузка словаря при запуске, со значениями переменных.
6. Полноэкранный редактор и пересборка.
7. Слово `palette!`; `video-mode` и `board-test` сделаны на этапе 3.

Позже: русский ввод (раскладка ЙЦУКЕН, переключение раскладки, коды
Unicode в событиях клавиатуры) и русские сообщения ff; мышь в редакторе;
другие слова для звука.


## 14. Открытые вопросы

- Имена слов терминала, не входящих в стандарт Forth 2012 (7.5).
- Палитра из 4 цветов (6.5).
- Размеры: стек задачи оболочки, `mem_limit`, наибольшая длина строки,
  глубина истории, период уступки процессора (5.3) — после замеров на
  первом этапе.
- Порог долгого нажатия K1: пока 1 с (раздел 12).
- Как `save` и пересборка обходятся со словами, созданными определяющими
  словами, со строками и с назначениями `is`, если доработка 2 из
  раздела 9 этого не покроет.
- Мышь в первой версии не используется.
